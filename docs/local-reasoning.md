# Local reasoning and message-vector reconciliation

`ollama` supports reasoning through its OpenAI-compatible `/v1` API and embeddings through `/api/embed`. Configure the model, dimensions and endpoint explicitly. Accepted HTTP hosts are loopback addresses, `localhost`, `host.docker.internal` and the Compose service alias `ollama`; aliases remain operator-controlled routing assertions. URL credentials, queries, fragments and unrelated paths are rejected. These clients disable ambient proxies and redirects and never use cloud API credentials.

`DERIVER_LOCAL_ONLY=true` validates the derivation model. `DIALECTIC_LOCAL_ONLY=true` validates every configured reasoning level and synthesis model. Either flag also rejects non-Ollama clients at runtime, including model overrides, and suppresses the optional Langfuse decorators/span updates. Ollama fallback models are rejected. Other modules with cloud model defaults must be explicitly configured for Ollama before use. These settings constrain model routing; they are not a process firewall or a claim that a selected server, database, DNS alias or other integration is trustworthy.

The Compose example binds published ports to loopback, requires a PostgreSQL password and uses the maintained `/readyz` probe. It disables telemetry exporters. Reasoning and vector reconciliation are separate opt-in profiles. No service is started by importing these source modules or by viewing the example. The API can still access its configured database/cache; operators remain responsible for selected endpoints, model availability, credentials and data authority.

The explicit `scripts/reconcile_message_vectors_local.py` command reads the configured PostgreSQL database even without `--execute`. Its scope is **all workspaces in that database**. It reports message/vector counts and sampled identifiers/content hashes. The vector-row count is a precondition only; no semantic search or retrieval quality is tested. Reports are private, exclusive files in the selected manifest directory; treat their identifiers and hashes as sensitive metadata.

Only `--execute` runs reconciliation. `--create-missing-embedding-rows` and `--release-leased-pending` additionally request their named mutations. `--max-batches` bounds reconciliation iterations; `--max-repair-rows` bounds each repair's selected input rows, and both accept 1–1000. Chunking can create more embedding rows than selected messages. A batch is not an atomic job: existing reconciler retries and earlier committed work remain if a later operation fails. No automatic rollback or total-database snapshot consistency is promised.

For this local maintenance entrypoint, select credential-free `ollama` transport (including for a local OpenAI-compatible server), PostgreSQL vectors and disabled telemetry exporters. Remote/external vector stores and credentialed cloud transports remain available through the existing general reconciliation facilities; they are deliberately outside this entrypoint's local transport contract. The CLI neither validates database locality nor activates the broad deriver, dream, document or summary queues.

The historical two-commit `arta/honcho-local-only-reasoning-20260721` source is retained in native history. Its removed intermediate policy tests are covered by maintained offline caller tests. Current `/health` and `/readyz` source/tests from PR32 are preserved. Qualification uses fictional HTTP transports, settings and SQL seams with network, real stores and child processes denied; it does not qualify a running Ollama model, PostgreSQL instance or Compose deployment.
